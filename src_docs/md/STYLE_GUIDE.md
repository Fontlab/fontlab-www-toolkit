# Style guide

Conventions for contributing to `fontlab-www-toolkit` and the consumer repos
that depend on it.

## Python code style

- **Formatter:** `ruff format` (line length 100, Python 3.12 target).
- **Linter:** `ruff check` with `E`, `F`, `I`, `UP` rule sets; `E501` ignored.
- **Type checker:** `mypy` with `check_untyped_defs = true`.
- **Python version:** `>=3.12` throughout; use `match`/`case`, `pathlib`,
  `dataclasses`, and bare union syntax (`X | Y`).

Run all checks locally:

```bash
uv sync --group dev
uv run ruff check src/ tests/
uv run ruff format --check src/ tests/
uv run mypy src/fontlab_www_toolkit/
uv run pytest tests/ -v
```

## File headers

Every source file must carry a `this_file:` record near the top, after any
shebang or module docstring, before the first import:

```python
# this_file: src/fontlab_www_toolkit/builder.py
```

For Markdown files:

```yaml
# this_file: src_docs/md/STYLE_GUIDE.md
```

Update on file move; verify before editing.

## Test naming

Tests follow the `test_{unit}_when_{condition}_then_{result}` pattern:

```python
def test_parse_frontmatter_when_webflow_url_present_then_returns_value() -> None: ...
def test_inject_badge_hiding_css_when_head_present_then_inserts_once() -> None: ...
```

For parametrised tests, the subject and variant are sufficient:

```python
@pytest.mark.parametrize("placeholder,expected", [...])
def test_cloudinary_placeholder_named_options(placeholder: str, expected: str) -> None: ...
```

## Test file organisation

| File | Scope |
|---|---|
| `tests/test_builder.py` | Core path helpers, config loading, file ops, webflow discovery |
| `tests/test_cloudinary.py` | `process_html_cloudinary` — all Cloudinary mapping and responsive image tests |
| `tests/test_html_processing.py` | Badge removal, Google Fonts splitting, Rocket Loader opt-out |
| `tests/test_markdownify.py` | `markdownify` integration fixtures (tables, images, script stripping) |

## Commit conventions

- One logical change per commit.
- Message format: `<imperative verb> <what>` (e.g. `Add mypy config to pyproject`).
- Do not amend published commits; create a new fix commit instead.
- Do not commit `wf_cache/`, `build_docs/`, or `public/` (all gitignored in
  consumer repos).

## Consumer repo conventions

Consumer repos (`www.fontlab.com`, `www.vexy.art`) must follow these rules:

| Convention | Detail |
|---|---|
| `src_docs/mkdocs.yml` | Required; ProperDocs build entry point |
| `static_docs/` | Verbatim overlay; no processing applied |
| `wf_cache/` | Git-ignored; regenerated by `pull-webflow` |
| `fontlab-www-toolkit.json` | Optional JSON config at repo root |
| Stub frontmatter key | Default `webflow-import-url`; override in config |

## Versioning

Version comes from git tags via `hatch-vcs`:

```bash
git tag v1.2.3
./publish.sh   # builds wheel + sdist, publishes to PyPI
```

The `fallback-version = "0.0.0.dev0"` sentinel is only used in development
checkouts without a tag.  It is never published; the CI build step (`uv build`)
runs from a tagged commit.

## Changelog

Maintain `CHANGELOG.md` with one `## vX.Y.Z — YYYY-MM-DD` section per release.
Entry format:

```markdown
## v1.1.0 — 2026-07-01

### Added
- New feature description.

### Fixed
- Bug fix description.

### Changed
- Breaking change description.
```
